# AI Мастер-план Эксперт VG

## Этап DATA AI · 26.11.2026

Добавлен отдельный локальный раздел `/data-ai`: реальные территории без учебных чисел, загрузка и хранение оригиналов в SQLite, извлечение текста PDF/DOCX/TXT/MD/CSV/JSON/GeoJSON, SHA-256, происхождение, просмотр текста, выбор источников, согласие на отправку в OpenAI, отчёты с цитатами и историей редакций.

**Статус подключения:** серверный адаптер OpenAI Agents API реализован. На момент сдачи ключ не размещён в окружении; живой запрос и доступ проекта к модели НЕ проверены. Успешная сборка не означает успешный AI-анализ.

### Подключить уже созданный ключ

На своём Mac откройте `Подключить ключ DATA AI.command` двойным щелчком или выполните `python3 scripts/configure-key.py` в Терминале из этой папки. Помощник показывает путь `.env.local`, требует подтверждения «да», принимает ключ скрытым вводом и записывает `OPENAI_API_KEY` с правами 0600. Не передавайте ключ в чат, командную строку или GitHub. Помощник отказывает для отслеживаемого Git файла или ссылки. `.env*` исключены из Git. Существующий ключ заменяется только после подтверждения; другие переменные сохраняются.

После сохранения перезапустите сервер. Наличие ключа не проверяет его валидность. Модель по умолчанию `gpt-6-astra` из текущего Agents API quickstart; переопределение — серверная переменная `OPENAI_DATA_MODEL`. Нужны разрешения Agents read/write и Responses write, доступ к модели и средства API-проекта.

### Обновление и запуск

```bash
npm install
npx prisma generate
npx prisma db push
npm run build
npm start
```

Перед изменением БД сделайте локальную резервную копию. Добавляются Territory, SourceDocument, DataAnalysis; старые Project/Run/Review сохраняются. `npm run db:setup` требуется только для чистой установки.

Войти девелопером → «Реальная территория · DATA AI» → создать территорию → загрузить документ с происхождением → проверить извлечённый текст → отметить источники → подтвердить передачу → запустить анализ. Отчёт сохраняется как черновик, не закрывает G0 и не изменяет расчётные вводные. Новые документы увеличивают редакцию: прежний отчёт явно помечается как относящийся к старому составу источников.

### Границы пилота

- Только localhost и доверенный пользователь компьютера; демо-роли не обеспечивают изоляцию сотрудников. Все локальные роли читают реальные материалы. Не публиковать сервер.
- Оригиналы и текст находятся в `prisma/dev.db`, не в публичной папке и не в Git. БД не зашифрована приложением: безопасность диска и резервных копий обеспечивает владелец компьютера.
- До 5 МБ на файл, до 100 страниц PDF, до 100 000 символов за анализ, до 20 документов на территорию. PDF/DOCX разбираются отдельным процессом с лимитом времени 20 секунд и JS heap 256 МБ. Это ограничение ресурсов, не полноценная песочница ОС; не загружайте неизвестные исполняемые материалы.
- Нет OCR; сканы, зашифрованные и нераспознаваемые документы отклоняются. GeoJSON пока читается как текст, не превращается в GIS-слой. DOCX размечается фрагментами, не страницами.
- В OpenAI передаются только выбранный извлечённый текст и сведения об источниках после согласия. Применяются правила хранения провайдера; формальная юридическая оценка передачи реальных данных не выполнена.
- Agents API: hosted small sandbox, внешняя сеть sandbox отключена, ключ не передаётся внутрь sandbox, tools пусты. Сессия ограничена 100 USD cents, запрос — 180 секунд; автоматические повторы отключены. Лимит сессии не заменяет контроль биллинга аккаунта.
- Сохраняются session/turn IDs. При успехе/ошибке выполняется cleanup; если он не завершён, новые запуски блокируются. Кнопка «Остановить и закрыть облачную сессию» повторяет отмену/удаление. При аварии до получения session ID нужна ручная сверка в Platform; повторный запрос не отправлять вслепую.
- Цитаты проверяются на точное присутствие в указанном источнике. Это не проверяет смысловую корректность вывода, подлинность или актуальность документа. Весь отчёт требует проверки человеком.
- Другие семь направлений и координатор в учебном кабинете остаются алгоритмами правил. Реальные GIS, финмодель, полноценная авторизация и промышленная эксплуатация не входят в этот этап.

# Мастер-план территорий · Ваш Выбор

Локальный рабочий MVP, версия **0.1.0 · 20.11.2026**. Отдельный продукт в стиле «Мой ИЖС», а не новый маркетплейс.

**Что реально работает:** ввод данных → проверка G0 → выбор маршрута → три алгоритмические схемы → экономика → независимая проверка другой ролью → решение → JSON-досье и журнал.

**Что важно:** восемь агентов представлены демонстрационным движком правил. Здесь нет подключённых LLM, настоящего GIS/CAD и подтверждения реализуемости реальных территорий. Все исходные данные и цены вымышлены. Это инструмент проверки продуктового сценария, не инструмент выпуска проектной документации.

## Быстрый запуск

Нужен Node.js 22.15+ и npm. Проверено на Node 26.13.0 / npm 11.20.0.

```bash
npm install
npm run db:setup
npm run dev
```

Открыть **http://127.0.0.1:3100**. Сервер слушает только локальный интерфейс. Для повседневного запуска на Mac также есть `Запустить.command`.

Если общий кеш npm имеет ошибку EACCES, используйте отдельный кеш без изменения системных прав:

```bash
npm install --cache /private/tmp/master-plan-npm-cache
```

Производственная сборка для **локальной** проверки:

```bash
npm run build
npm start
```

Не запускайте dev и start одновременно на порту 3100. `Ctrl+C` останавливает сервер. После перезапуска проекта данные сохраняются в `prisma/dev.db`. Первичное заполнение идемпотентно: существующие территории не затираются. Для резервной копии остановите сервер и скопируйте `prisma/dev.db`; база исключена из Git.

## Демо-аккаунты

Пароли, почта, телефоны и ключи не нужны. На странице входа доступны:

| Роль | ID | Действия |
|---|---|---|
| Девелопер | developer | Создание, вводные, расчёт, принятие проверенного результата |
| Независимый эксперт | expert | Проверка или возврат расчёта, комментарий |
| Администратор | admin | Просмотр всех проектов, истории, экспорт; без скрытого обхода согласования |

Это один учебный рабочий контур, а не многопользовательская изоляция компаний. Каждый пользователь этого компьютера может выбрать любую демо-роль. **Не размещать такой режим на публичном сервере.**

## Проверить за пять минут

1. Войти девелопером. Выбрать «Демо · Лесной квартал». Открыть «Варианты и экономика» → «Рассчитать варианты».
2. Сравнить A/B/C, площади, денежный поток, прибыль и стресс-сценарий. Просмотреть отчёты в «Команда Делика».
3. Выйти, войти экспертом. Открыть «Проверка и решение», написать заключение (от 10 символов), подтвердить или вернуть на доработку.
4. Войти девелопером, принять проверенный результат. Затем изменить вводные: старое заключение больше не разрешает принятие нового расчёта.
5. Проверить «Демо · Береговой парк»: условные сценарии, без SLA. Проверить «Демо · Южная территория»: варианты не формируются из-за блокера.
6. В «Досье проекта» скачать JSON со всеми редакциями расчётов и историей. Администратор может просматривать и экспортировать эти данные.

После автоматических тестов в локальной БД остаются территории с префиксом E2E — свидетельства проверки, не реальные проекты. На текущем компьютере «Лесной квартал» также уже прошёл браузерную проверку полного цикла. В чистой установке seed создаёт проекты без расчётов.

## Принятые допущения

- По уточнению владельца 20.11.2026 строится приложение мастер-планирования. Сценарии покупателей, партнёров, сделок и паспортов домов из вставленного ТЗ маркетплейса сюда не включены.
- Next.js + TypeScript + Tailwind; API Route Handlers; Prisma 6.19 + SQLite; seed. Внешних платных API и ключей нет.
- Основа: локальный кейс MP72-CASE-001 v1.1 от 20.11.2026 и регламент «Мастер-план территории за 72 часа». Исходные внутренние документы не публикуются в репозитории; здесь реализована согласованная часть требований.
- G0 содержит ровно десять пунктов. Нужны и отметка, и непустое основание. Подлинность введённого основания приложение не удостоверяет.
- Красный маршрут имеет приоритет; жёлтый возникает при отсутствии хотя бы одного из четырёх видов инженерных данных. В жёлтом маршруте не обещается срок 72 часа.
- Визуальный ряд G0–G5 — упрощённый демонстрационный статус. Настоящий SLA, план исполнителей и все доказательства приёмки 19 артефактов не реализованы.
- Территория — прямоугольник 100–2000 м по каждой стороне, локальные метры без геопривязки. Разделение на участки и зоны рассчитывается алгоритмом. Схемы не являются геоданными/кадастровым планом и не проверены по нормам минимальных размеров участков.
- Ширина улиц 12 м, зелень 16/25/33%, общественная зона 5%, количество рядов — учебные продуктовые допущения, а не нормативы.
- Экономика только продажи участков. Не включает строительство домов, налоги, НДС, кредит, дисконтирование, инфляцию и сезонность. Инфраструктура масштабируется по площади улиц, не считается по BOQ. Все затраты в квартале 0, два квартала подготовки, далее равномерная выручка.
- Окупаемость — первый квартал неотрицательного накопленного потока; при отсутствии возврата показывается «Не достигнут». Рекомендация ранжирует только модельную абсолютную прибыль, не объявляет вариант оптимальным по всем критериям.
- Стиль взят из существующего локального кода «Мой ИЖС»: #155EEF, #18253B, белый фон, Arial. Общий утверждённый брендбук и упомянутое исследование пока не найдены; соответствие всем продуктам холдинга не заявляется.
- Иконки Lucide (ISC); иконки PWA растеризованы из Lucide Layers. Нет внешних шрифтов, тайлов, фото и трекеров в прикладном коде.

## Структура

- `app/workspace.tsx`, `app/globals.css` — рабочее пространство и адаптивные экраны.
- `app/api/` — вход, создание, сохранение, расчёт, проверка, принятие, экспорт.
- `lib/domain.ts` — валидируемые вводные, маршруты, геометрия, экономика, отчёты правил.
- `lib/auth.ts` — локальный доступ, Origin, ограничение тела запроса, cookie-сессии.
- `prisma/schema.prisma`, `prisma/seed.ts` — User, Session, Project, Run, Review, AuditEvent и seed.
- `tests/` — тесты логики и HTTP E2E.
- `docs/` — ограничения, архитектура, проверка и изображения интерфейса.

Project хранит версионируемый снимок вводных, Run — неизменяемый результат и автора, Review — отдельного проверяющего. Изменение вводных увеличивает revision и сбрасывает согласование. Повторный расчёт требует новой проверки, даже если revision не изменилась. Проверяется ID конкретного расчёта.

## Доступность и слабая связь

Адаптивная компоновка проверена при ширине 390 px и 1440 px. Крупные основные кнопки, подписи полей, навигация клавиатурой, видимый фокус, ссылка пропуска навигации, текстовые таблицы рядом с визуализацией. Полного аудита WCAG и проверки со скринридером не проводилось.

PWA manifest + service worker: кешируются статические ресурсы и офлайн-страница. **Приватные страницы, API и данные проектов не кешируются.** Уже открытые данные можно читать при потере связи, новые загрузки/записи требуют работающего локального сервера. Фоновая синхронизация изменений и автономное редактирование не реализованы. Установка PWA не обязательна и не проверялась на iOS/Android.

## Безопасность и юридическая подготовка

Локальный bind, проверка Host/Origin, серверные роли, случайные HttpOnly/SameSite=Strict cookie-сессии на 8 часов, в БД только хеш токена, ограничение JSON до 32 КБ, валидация Zod, отсутствие HTML-инъекций, закрытый экспорт, запрет самопроверки. Ключей и реальных персональных данных в исходниках нет. Ноль известных зависимостных уязвимостей не является заключением об отсутствии всех дефектов.

Prisma 6.19 закреплена для SQLite. Транзитивные `effect` и `deepmerge-ts` обновлены через overrides из-за npm advisories; generate, db:setup, build и E2E проверяют совместимость. Снимать overrides без нового audit нельзя.

Checklist до реального использования: [docs/LEGAL-CHECKLIST.md](docs/LEGAL-CHECKLIST.md). Платежей, писем, эскроу, внешних заявок, электронных подписей и банковских интеграций нет.

## Следующие этапы

1. Владелец принимает один сквозной сценарий. Архитектор, инженер и экономист задают критерии на одной территории с разрешёнными к использованию данными.
2. DATA CORE: нормализованные источники, версии документов, даты, provenance и права доступа. Затем PostgreSQL + PostGIS, импорт границ, проверка координат и топологии.
3. GIS/CAD: реальные полигоны, слои ограничений, рельеф, коридоры, дороги и инженерия, экспорт в согласованные форматы, профессиональная приёмка.
4. Подключение выбранной модели отдельным серверным адаптером после выбора источника, бюджета и правил обработки данных. Сохранить детерминированные расчёты как инструменты и независимую проверку; LLM не подтверждает право и не считает финансы свободным текстом.
5. Поэтапная финансовая модель по объёмам, налогам, кредиту и продажам. Затем весь пакет A01–A19, SLA, очереди фоновых задач и экспертные подписи.
6. Производственный доступ: настоящая авторизация, организации/проектные ACL, rate limiting, аудит, резервирование, хранение в согласованной юрисдикции, юридическая приёмка и нагрузочные тесты. Только после этого размещение.

### Путь SQLite → PostgreSQL

Остановить запись, сделать копию SQLite. Добавить `DATABASE_URL` только в окружение, заменить datasource на postgresql, выпустить начальную миграцию на отдельной пустой PostgreSQL. Переносить сущности в порядке User → Project → Run → Review → AuditEvent с сохранением ID/дат/revision; сессии не переносить. JSON-снимки сначала сохранять без изменения, затем нормализовать отдельной миграцией. Проверить число строк, контрольные суммы снимков, связи, денежные расчёты, независимое согласование, конкурентные изменения и восстановление. Для нескольких пользователей добавить надёжные optimistic locks/изоляцию транзакций и ACL. Spatial-слои — в PostGIS после согласования CRS. Переход только сменой строки подключения без проверки не считается завершённым.
