# Архитектура MVP и граница агентности

Браузер → Next.js API → валидация/роль → SQLite transaction → снимок результатов.

DEVELOPER AI (Делик) в MVP — координатор вызова `runAnalysis`. DATA/LEGAL/GEO/PLAN/ENGINEERING/ECONOMY/ECO/AUDIT — именованные отчёты детерминированных правил одного процесса. Восемь автономных LLM, фоновые workers, инструменты поиска и автоматическое чтение документов **не подключены**.

Их подключение предполагается через серверный adapter: вход содержит только разрешённый снимок данных, запрос — цель и разрешённые инструменты, ответ — структурированный результат с источником, статусом достоверности и ошибками. Нельзя выдавать отсутствие источника за подтверждённое ограничение. Не использовать LLM для арифметики, геометрической топологии и окончательной юридической квалификации.

Постоянный DATA CORE: Project.data + revision, Run.result + revision + authorId, Review + reviewerId, AuditEvent. Снимки дают воспроизводимость исходного расчёта; документы и полноценный реестр происхождения данных — следующий этап. При переносе схемы на PostgreSQL учесть конкурентную запись; для текущей SQLite операции сериализуются в транзакции.

Геометрия — локальная прямоугольная модель в метрах. SVG является отрисовкой рассчитанных прямоугольников, не подложкой географической карты и не декоративной картинкой. Парковые/общественные полосы и улицы вычитаются из площади продаж. Все 27 комбинаций размеров/вариантов проверяются на отсутствие пересечений и баланс в unit-тесте.

Граница приёмки: приложение проверяет собственную математическую модель. Право, грунты, рельеф, мощности, спрос и стоимость реального освоения остаются неизвестными без профессиональных исходных данных. Статус «принят» означает принятие учебного результата внутри MVP.
